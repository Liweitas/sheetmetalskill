# 客户原始需求进入 PDF：2.8.47

## 数据及调用方式

在现有 MCP `sheetmetal_job` / HTTP 输入的 `brief` 对象内增加：

```json
{
  "customer_requirement_text": "客户最初提出本单需求的完整原话，保留原单位和换行。",
  "customer_requirement_updates": ["后续客户确认或修改的原话，按时间顺序追加。"]
}
```

这两个字段与 `dimensions`、`holes`、`handles` 等参数并列。原话是追溯信息，不是一个自然语言解析器；调用方仍须把已确认的尺寸、孔位和方向填入几何参数。模型摘要、默认值及推测不得当作客户原文。原文可保留旧尺寸，后续修订另列；制造图页显示本版实际采用参数。

新出图必须提供非空字符串 `customer_requirement_text`。修改记录数组可省略；提供时每条必须为非空字符串。类型、空白及不支持的控制字符检查在创建 CAD 工作目录前执行。旧调用方需补录真实原文；API 本身无需新增顶层参数或另开 PDF 管线。

## 同源输出

`brief` → `pipe_brief()` → `pipe.json` → 同一金样 `engine_u_endplates.py` → 工艺 PDF 末尾的客户需求页。

- U＋端板与 U围＋L 共用该实现，原工艺页顺序不变，页码包含新增需求页。
- 原文按原单位和换行显示；后续客户消息单列，长文本自动续页，字号不低于现有 9.4pt。
- 文本中的美元符号、下划线等按普通文字打印，不解析为绘图库公式。
- ZIP 的 `DOC/*_CUSTOMER_REQUIREMENT.txt` 保留 UTF-8 原文，已有 `EVIDENCE/*_source_brief.json` 与解析参数包含原文和修改记录。
- `bend_pdf_meta.json` 记录需求页数和原文字节 SHA256；新页参加既有重叠/越界检查与金样五文件哈希门禁。

直接重绘历史数据而缺原文时，会明确显示缺失，不从参数反编客户原话。正式新出图入口仍拒绝缺原文输入。仅实现文字追溯；未增加图片嵌入、OCR 或自动判断原文与参数冲突的功能。
